## Overview

Admin UI for the Service Mesh Control Plane. The application provides operators with an interface for:

- Viewing the service registry and its instances
- Managing routing rules (weighted routing, canary)
- Monitoring data plane node status

Architecture: **DDD-inspired** with strict layer separation. Data is stored locally first (local-first via TanStack Query persist).

## Architecture

Code is organized by **features** (`features/`) and **layers** (layered architecture).

### Layers

| Layer | Directory | Responsibility | Examples |
|---|---|---|---|
| **Domain** | `domain/` | Pure types, validation schemas, pure functions | `schema.ts`, `types.ts`, `useRoutingRulesUI.ts` |
| **Application** | `application/` | Hooks, use cases, orchestration | `useRoutingRules.ts`, `useRuleForm.ts` |
| **Infrastructure** | `infrastructure/` | API clients, HTTP requests, mocks | `api.ts`, `mock.ts` |
| **UI** | `ui/` | React components, pages, CSS Modules | `RoutingRulesPage.tsx`, `RulesTable.tsx` |
| **Shared** | `shared/` | Common UI primitives, utilities, tables | `Button/`, `Dialog/`, `DataTable.tsx` |
| **Routes** | `routes/` | File-based TanStack Router routes | `index.tsx`, `services.tsx` |

### Principles

- **Local-first** — Data is cached in `localStorage` via TanStack Query persist.
- **Effect for HTTP** — `lib/http.ts` provides `apiFetchEffect<T>()` (Effect) and `apiFetch<T>()` (Promise wrapper for TanStack Query).
- **Zustand for UI state only** — Sidebar collapsed, selected service ID.
- **CSS Modules + CSS custom properties** — No Tailwind. Design tokens live in `index.css`.
- **Barrel exports** — Each feature exports its public API through `index.ts`.
- **Parse, don't validate** — Zod / Effect Schema at the boundary, not in the domain.

## Common Patterns

### Local-First Cache

Data is cached in `localStorage` via `query-sync-storage-persister`. On page reload, the UI shows cached data instantly and syncs with the server in the background.

```typescript
// lib/queryClient.ts
import { createSyncStoragePersister } from '@tanstack/query-sync-storage-persister';
import { QueryClient } from '@tanstack/react-query';

export const queryClient = new QueryClient({
  defaultOptions: { queries: { gcTime: 1000 * 60 * 60 * 24 } },
});

export const persister = createSyncStoragePersister({
  storage: window.localStorage,
});
```

### Effect-Based HTTP

`lib/http.ts` provides two APIs:
- `apiFetchEffect<T>()` — For composition in Effect pipelines (retry, timeout).
- `apiFetch<T>()` — Promise wrapper for use in TanStack Query.

```typescript
import { apiFetch } from '@/lib/http';

const services = await apiFetch<Service[]>('/services');
```

### CSS Modules + Design Tokens

Styles are written in `*.module.css`. Global design tokens live in `index.css`:

```css
/* index.css */
:root {
  --color-primary: #2563eb;
  --space-4: 1rem;
  --radius-lg: 0.5rem;
}
```

### Barrel Exports

Each feature exports its public API through `index.ts`:

```typescript
// features/routing-rules/index.ts
export { RoutingRulesPage } from './ui/RoutingRulesPage';
export { useRoutingRules } from './application/useRoutingRules';
export { RuleFormSchema } from './domain/schema';
```

## File Naming Conventions

| Pattern | Purpose |
|---|---|
| `*.tsx` | React components and pages |
| `*.module.css` | Component scoped styles |
| `*.ts` | Pure TypeScript modules (hooks, utilities, types) |
| `domain/*.ts` | Domain layer: types, schemas, pure functions |
| `application/*.ts` | Application layer: hooks, use cases |
| `infrastructure/*.ts` | API clients, mocks, HTTP adapters |
| `ui/*.tsx` | Feature React components |
| `*.test.ts` / `*.test.tsx` | Unit / component tests (co-located) |
| `routes/*.tsx` | File-based TanStack Router routes |
| `shared/ui/*/` | Common UI design system primitives |

## Commands

```bash
# Install dependencies
npm install

# Dev server (Vite) → http://localhost:5173
npm run dev

# Production build
npm run build       # tsr generate && tsc -b && vite build

# Preview production build
npm run preview

# Type-check
npm run typecheck   # tsr generate && tsc --noEmit

# Tests
npm run test        # vitest run (single run)
npm run test:watch  # vitest (watch mode)
npm run test:ui     # vitest --ui

# Lint
npm run lint        # tsr generate && eslint src
npm run lint:fix    # tsr generate && eslint src --fix
```

## Testing

- **Runner:** Vitest
- **Environment:** jsdom
- **Setup:** `src/test/setup.ts` imports `@testing-library/jest-dom`
- **Location:** Tests are co-located next to components (`*.test.tsx`, `*.test.ts`)
- **Libraries:** React Testing Library, User Event
- **Target coverage:** ≥ 80%

**Example: run routing-rules feature tests**

```bash
npx vitest run src/features/routing-rules
```
